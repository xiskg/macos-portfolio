From an interruption to a state model

The project addresses Wi-Fi interruptions during cloud gaming on macOS. Its README identifies AWDL and Continuity activity as the motivation. The implementation targets the Boosteroid native app by foreground-application name; browser use requires a manual override.

This is a personal utility, not a product integration or an endorsement. No independent latency benchmark or service adoption is claimed here.

Separate intent, observation and timing

The public implementation combines workspace notifications with a two-second status check. It tracks manual override, observed service state and an inactivity timer. Returning to the target application cancels the timer; leaving it can start a configurable grace period.

A bounded grace period

The timer is invalidated before a new one is created. Its completion restores services and clears the countdown state. This excerpt shows the transition rather than the privileged commands.

    func startInactivityTimer() {
        inactivityTimer?.invalidate()

            self.disableGamingMode()
            self.timerEndDate = nil
            self.inactivityTimer = nil
        }
        inactivityTimer = t
        RunLoop.main.add(t, forMode: .common)

The operational cost of convenience

The app changes system-service and interface state using privileged commands. That makes permission scope, restoration and failure reporting central concerns. The current code uses a shell wrapper with limited error propagation; an explicit success result would make the displayed state more trustworthy.

Next improvements I would prioritize: deterministic state-transition tests, verified command outcomes, a termination/restoration policy and signed distribution. Those are proposed improvements, not features claimed to exist.

What the source supports

  • Foreground-app detection, a manual override and timed restoration are implemented.
  • A Swift build script and a Homebrew cask are present.
  • Performance improvements, crash recovery and behavior across macOS versions are not independently validated in this case.
